DeadlineDesk

A Campus Web System for Placement Rounds and Academic Assignment Deadlines

Overview

Three-sentence summary

ProblemPlacement rounds and assignment cutoffs are scattered across WhatsApp, Drive folders, and LMS notices.
ApproachDeadlineDesk unifies a Placement Track and an Academic Dropbox in one role-based web system.
OutcomeStudents complete checklists and submissions on time; TAs apply late policy consistently; progress is measurable.
UCS503P · Project Proposal · W42 / 8
1 · Problem Statement

Why the project is needed

Placement side

  • Company rounds tracked in sheets and chats
  • Document checklists are informal
  • Reminders are ad-hoc; windows are missed

Academic side

  • Submissions via Drive or email
  • Late policy applied manually
  • Grade and late status lack transparency
Stakeholders: students, TAs/faculty, placement coordinators3 / 8
2 · Objectives

SMART outcomes for the semester

Primary goal: a working, testable deadline system by Week 7; design depth and quality for EST.

  1. Role-based auth for Student, TA/Faculty, Placement Admin (with login tests)
  2. Placement path: company/round → document checklist → T−24h reminder log
  3. Academic path: assignment + late policy → submit → late flag → similarity stub → grade
  4. ≥ 5 automated tests; 100% agreement with late-policy rules on a fixed suite
  5. CI on every push; MkDocs documentation site via GitHub Pages

3 · Proposed Solution

Two modules, one shared core

Shared coreAuth · Roles · Deadlines · Documents · Reminders

Placement Track

  • Companies and rounds
  • Document checklists
  • Reminder schedule (T−72h / T−24h)

Academic Dropbox

  • Assignments with late policy
  • File submit and late flag
  • Similarity stub and TA grade
